### Task 260: A restart ends autopilot (FR1) — [x]

- **Description:** `restartGame` (`src/net/game.ts`) calls `seatBots(game, botSeatsOf(game))`.
  `botSeatsOf` reads `game.bots`, which includes the autopilot seat, because `setAutopilot` seated a bot
  there. `seatBots` then clears `game.autopilot`. After a passed `"room"` vote the result is:
  - the seat has a bot again but autopilot is empty;
  - `attach.ts` stops ignoring the person's input on that seat, and a higher `seq` locks out the bot;
  - `setAutopilot(..., false)` returns early, so the person cannot get the seat back until `advanceRoom`.

  The fix: `restartGame` seats bots only on bot seats that are not autopilot seats
  (`botSeatsOf(game).filter((s) => !game.autopilot.has(s))`). That matches the existing comment above
  `seatBots`: "Autopilot ends here too: every caller but setAutopilot (… a restart …) leaves it off".
- **Files touched:** `src/net/game.ts`, `src/net/game.test.ts` (the autopilot cases are near l.1142).
- **Tests first (red):** a unit test in `src/net/game.test.ts`:
  1. Use a lobby with one lobby bot on seat 2. Call `setAutopilot(game, lobby, 1, true)`, then
     `restartGame(game)`.
  2. Expect `game.bots[1]` to be undefined, `autopilotOn(game, 1)` to be false and `game.bots[2]` to
     still exist.
  3. Expect `setAutopilot(game, lobby, 1, true)` to return true afterwards.

  Today `game.bots[1]` is still set, so the test fails.
- **Acceptance criteria:**
  - The new test passes, and the existing `restartGame` and autopilot tests in `src/net/game.test.ts`
    still pass.
  - `spec/autopilot.test.ts` and `spec/restart-resume.test.ts` stay green.
  - `pnpm check` is green.
- **Break check:** a script that asserts the text `seatBots(game, botSeatsOf(game.filter` form it
  replaces, restoring the old `seatBots(game, botSeatsOf(game))`. The new test goes red. Restore.
- **Depends on:** none.
