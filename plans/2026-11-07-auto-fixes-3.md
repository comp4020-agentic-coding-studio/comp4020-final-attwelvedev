## 1. Summary

One fix to what the server sends a sighted seat. The playtest fix for L1 (a figure vanished while part of it was lit) made the server send a floor thing outside the tile set when its footprint is partly lit. The rule is in `src/game/perception.ts` (about l.1007 to 1015). But the server also requires the figure's **own** tile to be lit (`lit({ x: floor(pos.x), y: floor(pos.y) })`). A figure at x = 6.9 covers x from 6.54 to 7.26 (its half is 0.36, from `footHalf("player")`). If tile 6 is dark and the lit strip lies in tile 7, the server never sends the figure, even though the client's `litEntities` would draw it from that strip. So the comment "by the client's own rule" is not true.

The regression test for L1 (`src/client/render/standing.test.ts`, "draws a figure whose feet are partly lit…", about l.1867) cannot catch this. It places every figure at a tile centre (`fx + 0.5, fy + 0.5`), so its footprint never leaves its own tile. Under that condition the own-tile gate never changes the answer.

The task first widens the sweep with off-centre figures and shows it red against today's server gate. Then it changes the gate so that any tile the footprint overlaps can let the figure through. `footLit` stays as the final test. No test is weakened.

The verifier read both findings against the code at `62ac82a` and confirmed that nothing after that commit touches `perception.ts`, `sight.ts`, `light.ts` or `standing.test.ts`. The verifier did not run a room to find a real spot where this happens ("geometry I didn't run"). So the task starts by reproducing the case. If the widened sweep finds no figure lost in rooms 6 and 8, the task builds the case by hand in a unit scene. If even that cannot produce the case, nothing is fixed, and the result goes to `specs/backlog.md` as one dated line.
